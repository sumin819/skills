# 검증된 상태로 제출 준비하기

과제의 제출 조건과 성공 기준을 다시 읽는다. 이 시점에서 불필요한 새 기능을 추가하지 않는다.

요구사항마다 `구현 위치 / 검증 입력 / 기대 결과 / 실제 결과 / 상태`를 연결한다. 상태는 통과, 실패, 미검증으로 구분한다. 정상 입력뿐 아니라 과제에 중요한 빈 입력, 잘못된 값, 중복, 경계값, 의존성 실패를 선정한다. 모든 프로젝트에 같은 테스트 목록을 강요하지 않는다.

기존 테스트·빌드 명령이 있으면 실행한다. 여러 명령을 기록해야 한다면 키트의 `scripts/checks.py`를 사용할 수 있다. 검증 설정은 신뢰할 수 있는 명령인지 먼저 읽고 실행한다. 테스트 종료 코드만으로 UI·업무 목표까지 검증됐다고 판단하지 않는다.

가능하면 기록된 실행법으로 새 프로세스에서 재현한다. 필요한 입력·환경 변수 이름·설치 절차를 확인하되 비밀값을 문서에 넣지 않는다. 외부 서비스가 없어도 동작해야 하는 과제라면 실제로 해당 조건을 확인한다.

과제 지정 문서 또는 `PRD.md`에 실행 명령, 검증 결과, 핵심 구조, 알려진 한계와 제출 경로를 정리한다. 미확인 항목은 그대로 남긴다. 출제자가 준 파일, 개인 메모, 불필요한 로그를 임의로 삭제하지 않는다.

최종 보고에는 만든 결과, 검증 근거, 실행 방법, 남은 문제를 담는다. 로컬 제출 준비와 플랫폼 제출 완료를 구분한다. 실제 제출·push·외부 공유를 자동 수행하지 않는다.
