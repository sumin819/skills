# 답을 바꾸는 질문 만들기

원문과 기존 대화에서 이미 확인한 내용을 먼저 읽는다. 담당자 대화를 직접 볼 수 없다면 사용자가 전달한 내용만 근거로 삼는다. 메시지를 직접 전송하지 말고 사용자가 전달할 문안을 준다.

가장 큰 불확실성에 맞춰 질문을 고른다. 질문을 모두 한꺼번에 나열할 필요는 없다.

- 업무 문제: “최근 실제로 문제가 된 사례 하나에서, 누가 무엇을 보고 어떤 결정을 했나요?”
- 우선순위: “이 두 문제 중 하나만 먼저 해결한다면 어느 쪽의 손실이 더 큰가요?”
- 성공 기준: “현재 걸리는 시간이나 오류 규모는 어느 정도이며, 어느 수준이면 도움이 되나요?”
- 경계 조건: “값이 없거나 판단이 애매한 경우 지금은 어떻게 처리하나요?”
- 권한·결과: “이 결과는 참고용인가요, 실제 처리까지 자동으로 이어져야 하나요?”

답변을 받으면 `관찰된 문제 → 요구사항 → 성공을 확인할 입력·출력`으로 바꾼다. 답변 원문을 장황하게 복제하지 말고 해석과 미확인 사항을 분리한다. 사용자 확인 없이 새로운 요구사항을 확정하지 않는다.

담당자의 기대가 데이터나 시간상 불가능하면 이유를 증거와 함께 설명하고 A/B 선택지를 만든다. 합의가 필요한 부분을 임의로 우회하지 말고 독립적으로 가능한 일을 계속한다.

진척 전달 문안은 문제, 만든 것, 실제 검증 결과, 남은 한계, 다음 확인 요청 순으로 짧게 쓴다. 숫자는 측정한 것만 사용한다.
